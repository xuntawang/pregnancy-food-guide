# 孕期个护速查实施计划

> **供执行人员阅读：**必须逐任务使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 执行本计划。每一步都使用复选框（`- [ ]`）跟踪进度。

**目标：**将现有中文“孕期饮食速查”扩展为移动端优先的“饮食 / 个护”统一工具，为个护成分、常见商品、日常美容项目和医美项目提供可追溯、结合使用场景的孕期建议。

**架构：**线上仍使用一个自包含的 `index.html`，不依赖服务器。个护资料保存为四组内嵌 JSON；纯规则判断引擎也内嵌在页面中，并通过 `globalThis.personalCareEngine` 暴露稳定接口。测试使用 Node.js 自带能力从 HTML 中提取数据和引擎，既验证医学证据约束，也保护原有饮食功能。

**技术栈：**语义化 HTML、CSS、原生 JavaScript、内嵌 JSON、Node.js 内置 `node:test`／`node:assert`／`node:vm`、GitHub Pages。

## 全局约束

- 线上运行文件保持为单个自包含 `index.html`，不得加入运行时 API、CDN、远程字体、统计脚本、账号体系、OCR 或 AI 依赖。
- 保留现有全部食物资料和搜索行为。只有在回归测试保护下，才允许调整饮食与个护共用的界面组件。
- 四种用户可见结论及内部键值固定为：
  - `safe` → 通常可用
  - `limit` → 限制使用
  - `avoid` → 建议避免
  - `consult` → 证据不足／咨询医生
- 组合判断优先级固定为 `avoid > limit > consult > safe`。“证据不足”表示不确定性，不得盖过已知的限制或避免结论。
- 不得宣称“绝对安全”。“通常可用”仅表示在卡片所列条件下通常可以使用，不能替代个体化医嘱。
- 每条 `limit`、`avoid`、`consult` 规则必须关联至少一个权威来源和复核日期。
- 来源优先级固定为：中国国家药监局及国内专业指南；ACOG、FDA、EMA、NHS；MotherToBaby、UKTIS/BUMPS；系统综述或正式专家共识。
- 品牌、商品包装和零售页面只能证明“这一版本的配方是什么”，不得单独作为孕期医学判断依据。
- 商品快照必须标注配方地区、配方复核日期和配方来源。超过 365 天未复核时，页面自动降级为 `consult`。
- 成分表分析必须完全在浏览器本地完成。不得保存搜索词、商品名、粘贴的成分表或分析结果。
- 唯一允许使用的本地存储键是 `pregnancy-guide-channel`，只用于记住“饮食 / 个护”频道。
- 偶发的一次使用不能被描述成紧急事件。只有出现真实危险症状时才提示紧急就医。
- 页面必须保留清晰、可见的医学免责声明。
- 首发最低资料量：
  - 80 条成分或成分家族规则
  - 40 条商品类别、美容或医美项目规则
  - 30 个经过配方核实的常见商品快照
- 日期统一为 `YYYY-MM-DD`，外部证据链接统一使用 HTTPS。
- 所有需要用户审阅的说明、证据台账、核查清单和发布记录以中文为主；代码标识、命令、INCI 成分名和机构原名可保留英文。
- 每个任务结束前运行完整测试，只有通过后才提交。
